---
title: 'Search Jobs'
api: 'POST /v2/jobs'
description: 'Search LinkedIn job postings and read one, including who posted it.'
---

## Overview

Search job postings with the filters of LinkedIn's Jobs tab, paginated with `count` and `offset`. Works with any LinkedIn account.

<Note>This endpoint consumes **1 credit per 10 results** returned. Ignore this if you're on per-seat pricing: usage is unlimited.</Note>

## Request

<ParamField header="x-api-key" type="string" required>
  Your API key for authentication.
</ParamField>

<ParamField body="account_id" type="string" required>
  The unique identifier of the account to use.
</ParamField>

<ParamField body="action" type="string" required>
  Must be `"search"`.
</ParamField>

<ParamField body="params" type="object" required>
  <Expandable title="params properties">
    <ParamField body="keywords" type="string">
      Job title, skill or company. Required unless a location is given.
    </ParamField>
    <ParamField body="location" type="string">
      Location as text (`"Paris"`, `"Germany"`). Or `location_id`: the geo id from [Typeahead](/api-reference/v2/profiles/typeahead) or from a previous response.
    </ParamField>
    <ParamField body="sort_by" type="string">
      `"recent"` or `"relevant"`.
    </ParamField>
    <ParamField body="date_posted" type="string | integer">
      `"24h"`, `"week"`, `"month"`, or a number of seconds.
    </ParamField>
    <ParamField body="experience" type="string | string[]">
      `internship`, `entry`, `associate`, `mid_senior`, `director`, `executive`.
    </ParamField>
    <ParamField body="job_type" type="string | string[]">
      `full_time`, `part_time`, `contract`, `temporary`, `volunteer`, `internship`, `other`.
    </ParamField>
    <ParamField body="workplace" type="string | string[]">
      `on_site`, `remote`, `hybrid`.
    </ParamField>
    <ParamField body="company" type="string | string[]">
      Company ids. Same for `industry`, `function` and `title` ids.
    </ParamField>
    <ParamField body="easy_apply" type="boolean">
      Only Easy Apply jobs. Other flags: `in_network`, `under_10_applicants`, `verified`.
    </ParamField>
    <ParamField body="count" type="integer" default={10}>
      Number of jobs to return. Capped at `100` per call; paginate with `offset`.
    </ParamField>
    <ParamField body="offset" type="integer" default={0}>
      Use `pagination.next_offset` from the previous response. LinkedIn returns the first 1,000 results.
    </ParamField>
  </Expandable>
</ParamField>

## Response

<ResponseField name="data" type="object">
  <Expandable title="data properties">
    <ResponseField name="jobs" type="array">
      The jobs: `linkedin_job_id`, `job_url`, `title`, `company_name`, `company_url`, `company_id`, `location`, `listed_at` (ms), `easy_apply`, `promoted`, `reposted`, and LinkedIn's own texts when shown: `salary_text`, `benefits_text`, `applicant_insight`, `insight`.
    </ResponseField>
    <ResponseField name="total_results" type="integer">Number of jobs returned.</ResponseField>
    <ResponseField name="total_available_results" type="integer">Total number of jobs matching the search.</ResponseField>
    <ResponseField name="location_id" type="string">The geo id the search ran on.</ResponseField>
    <ResponseField name="pagination" type="object">`offset`, `count`, `next_offset`, `has_more`.</ResponseField>
  </Expandable>
</ResponseField>

## Get a job

Same endpoint, action `"get"` with `job_id` or `job_url`. 1 credit.

- Returns `title`, `description`, `job_state`, `company_name`, `company_url`, `location`, `workplace_type`, `employment_status`, `experience_level`, `industry`, `job_functions`, `listed_at`, `expire_at`, `salary`, `benefits`, `closed` and `viewer` (`applied`, `saved`).
- `apply`: `type` (`"easy_apply"` or `"external"`), `url`, and `company_apply_url` when the employer has its own page.
- `hiring_team`: who posted the job, each with `name`, `role`, `job_title`, `profile_url`, `profile_urn`, `profile_picture`, `connection_level`. Empty when LinkedIn shows nobody.
- An unknown job returns `INVALID_PARAMS` with `sub_code: "JOB_NOT_FOUND"`.

## Apply to a job

Easy Apply jobs only (`apply.type: "easy_apply"`), same endpoint. 1 credit each.

- `"get_apply_form"` with `job_id` or `job_url`: the `questions` to answer, each with `question_id`, `label`, `type`, the `pattern` an answer must match and the `value` LinkedIn pre-fills (email, phone, resume on file). `can_apply` is `false` when the form holds a question type not supported yet (choice, checkbox, date, upload).
- `"apply"` with `job_id` and `answers` (`{question_id: answer}`): submits the application. Pre-filled questions can be left out. Nothing is sent if an answer is missing or invalid (`MISSING_ANSWERS`, `INVALID_ANSWER`).
- Other errors: `NOT_EASY_APPLY`, `ALREADY_APPLIED`, `UNSUPPORTED_FORM`.
