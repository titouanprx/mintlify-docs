LinkupAPI serves the Unipile v1 API: same routes, parameters, responses, errors, pagination and webhook payloads. Your code keeps working; only the base URL and the key change.

<Note>
  The Unipile-compatible API is enabled per workspace. Ask [support@linkupapi.com](mailto:support@linkupapi.com) to turn it on. Until then, every call answers `403 errors/feature_not_subscribed`.
</Note>

## 1. Base URL and key

| | Unipile | LinkupAPI |
|---|---|---|
| Base URL | `https://{YOUR_DSN}` | `https://api.linkupapi.com/compat` |
| Routes | `/api/v1/...` | `/api/v1/...` (unchanged) |
| Header | `X-API-KEY: <Unipile token>` | `X-API-KEY: <LinkupAPI API key>` |

```bash
curl https://api.linkupapi.com/compat/api/v1/accounts \
  -H "X-API-KEY: YOUR_LINKUPAPI_API_KEY"
```

With the Unipile Node SDK, pass the LinkupAPI base URL as the DSN:

```js
const client = new UnipileClient("https://api.linkupapi.com/compat", "YOUR_LINKUPAPI_API_KEY");
```

Your API key is in the [dashboard](https://app.linkupapi.com). Scoped API keys work the same way.

## 2. Link your Unipile workspace

One call, with your Unipile DSN and key:

```bash
curl -X POST https://api.linkupapi.com/compat/api/v1/migration/unipile \
  -H "X-API-KEY: YOUR_LINKUPAPI_API_KEY" -H "Content-Type: application/json" \
  -d '{"dsn": "api8.unipile.com:13851", "api_key": "<your Unipile API key>"}'
```

From then on:

- **Every account keeps working from day one.** Requests on an account still at Unipile are relayed to your Unipile workspace and answered as before. `GET /accounts`, and `GET /chats`, `/messages`, `/chat_attendees` without `account_id`, list both sides.
- **Your webhooks are copied** (same URL, source, events, headers, accounts). Webhooks you create or delete later are mirrored at Unipile while it is linked.

Your Unipile key is stored encrypted and only sent to your Unipile DSN. `GET /api/v1/migration/unipile` shows the progress and copies webhooks you created at Unipile since; `DELETE` removes the link.

| Option | Default | |
|---|---|---|
| `new_accounts` | `"linkupapi"` | Where new accounts go. `"unipile"` keeps Unipile your default: new accounts and reconnections stay there, accounts move only when you say so. |
| `delete_moved_accounts` | `true` | Delete an account from Unipile once it works on LinkupAPI. `false` keeps it there too (you then receive its webhooks from both). |

## 3. Move your accounts, at your pace

Sessions cannot be moved from Unipile: each account connects once on LinkupAPI. Reconnect it **under its Unipile `account_id`**:

- Hosted link: `POST /api/v1/hosted/accounts/link` with `type: "reconnect"` and `reconnect_account: "<Unipile account_id>"`.
- Native: `POST /api/v1/accounts/{Unipile account_id}` with the credentials, as for a Unipile reconnection.

The account keeps its id. Once it works on LinkupAPI, it is deleted from your Unipile workspace (only if it is the same LinkedIn member, phone or mailbox), so nothing is sent twice. When every account has moved, unlink Unipile.

A new account (`type: "create"` or `POST /api/v1/accounts`) is created on LinkupAPI with a new id, as on Unipile.

## Keep Unipile alongside

To move only some accounts and keep the rest on Unipile for good, link with `"new_accounts": "unipile"`. Your Unipile accounts keep working through LinkupAPI as they are, and you move the ones you choose:

```bash
curl -X POST https://api.linkupapi.com/compat/api/v1/migration/unipile/accounts/{Unipile account_id} \
  -H "X-API-KEY: YOUR_LINKUPAPI_API_KEY" -H "Content-Type: application/json" -d '{}'
```

With an empty body you get a hosted link (`HostedAuthUrl`) to send to the account's owner; it takes `notify_url`, `name`, `expiresOn`, `success_redirect_url`, `failure_redirect_url`. With the Unipile native-auth body (`provider`, `username`, `password`…) the account is reconnected right away. Either way it keeps its id.

## Webhook events

Payloads match Unipile's, field for field. Supported sources and events:

| Source | Events |
|---|---|
| `messaging` | `message_received`, `message_read`, `message_reaction`, `message_edited`, `message_deleted`, `message_delivered` |
| `users` | `new_relation` |
| `account_status` | `ok`, `credentials`, `creation_success`, `reconnected`, `deleted` |
| `email` | `mail_received`, `mail_sent` |

## What differs

- **Chat, message and attendee ids** change when an account moves: list its chats again. Ids stored from Unipile no longer resolve for that account.
- **`GET /api/v1/messages`** (every message of an account) is available a few minutes after the account connects.
- **Filters LinkedIn no longer applies** are accepted and have no effect: job `benefits`, `minimum_salary`, `commitments`, `fair_chance_employer`, `location_within_area`; people `open_to`; classic company `industry`, `has_job_offers`, `network_distance`; Sales Nav `technologies`, `mentionned_in_news`.
- **Anything not supported** answers `501 errors/feature_not_implemented`, with the parameter or route in `detail`. A request is never run with a filter silently dropped.

## Coverage

**Providers:** LinkedIn (classic, Sales Nav, Recruiter Lite), WhatsApp, Gmail, Outlook, IMAP.

| Area | Supported |
|---|---|
| Accounts | Connect, reconnect, hosted links, checkpoints, list, get, delete, restart, proxy |
| Messaging | Chats, messages, attachments, reactions, attendees, InMail (classic, Sales Nav, Recruiter), group chats, mute, archive, delete |
| Users | Profiles, own profile and edit, relations, followers, invitations, posts, comments, reactions |
| Posts | Create, get, comments and replies, reactions (posts and comments) |
| LinkedIn search | Classic people, companies, jobs, posts; Sales Nav people and companies (saved and recent searches); Recruiter; search parameters |
| LinkedIn | Companies, InMail balance, contracts, raw data, Sales Nav lists (`saveLead`), Recruiter projects and pipeline, job postings and applicants |
| Email | Emails, folders, drafts, attachments |
| Webhooks | Sources above |

**Not supported yet** (they keep working through Unipile for accounts not moved yet): calendars, email tracking, Instagram, Telegram, X, Messenger, Recruiter job postings (`service: RECRUITER`), `addApplicantToPipeline`, skill endorsements, post targeted audience, paid job publishing and its checkpoint, Recruiter session sign-out, Recruiter Pro filters.
