## Overview

Manage the seat's **hiring projects** — the Recruiter equivalent of a lead list — and the candidates inside them. One endpoint, the `action` picks the operation.

Uses the account's Recruiter seat — see [Connect Account](/api-reference/v2/accounts/login#recruiter-seat). Pass the **seat's `account_id`**. Candidates come from [Search People Recruiter](/api-reference/v2/profiles/search-people-recruiter).

<Note>Each action consumes **1 credit**, `list_project_candidates` **1 credit per 10 results**. Ignore this if you're on per-seat pricing: usage is unlimited.</Note>

## Request

<ParamField header="x-api-key" type="string" required>
  Your API key for authentication.
</ParamField>

<ParamField body="account_id" type="string" required>
  The Recruiter seat's account id.
</ParamField>

<ParamField body="action" type="string" required>
  One of the actions below.
</ParamField>

<ParamField body="params" type="object">
  Depends on the action — see each one below.
</ParamField>

## Actions

| Action | Params | Does |
|---|---|---|
| `list_projects` | `count`, `offset`, `state` (`ACTIVE` default, `CLOSED`, `DRAFT`) | The seat's projects, each with its `hiring_states` (stages) and `candidate_counts` per stage. |
| `create_project` | `name`, `description`, `private` (default `true`) | Creates a project. Returns its `project_urn`. |
| `add_to_project` | `project_urn`, `candidate_urn` | Files a candidate into a project. |
| `list_project_candidates` | `project_urn`, `count`, `offset`, `states` | The pipeline: everyone in the project, in the search result shape, each with their `hiring_state`. `states` filters on stages. |
| `get_project_candidate` | `project_urn`, `candidate_urn` | Where one candidate stands: stage, how they were sourced, when they were added. |
| `move_candidate` | `project_urn`, `candidate_urn`, `state` | Moves a candidate to another stage. |
| `add_note` | `candidate_urn`, `text` | Leaves a note on a candidate, visible to the whole contract. |
| `get_candidate_notes` | `profile_urn` | The notes and tags held on a candidate. |
| `recommended_candidates` | `project_urn`, `count`, `offset` | LinkedIn's recommended matches for the project. |

- `candidate_urn` is the candidate's `hire_identity_urn` from the search; `profile_urn` is their `profile_urn`.
- `project_urn` is the urn from `list_projects` / `create_project` (a `project_id` works too).
- `state` takes the stage name as the project shows it (`"contacted"`, `"uncontacted"`), its status type (`CONTACTED`…) or its urn from `hiring_states`. The stage shown as "uncontacted" has the status type `SHORTLISTED`.

## Typical flow

1. [Search People Recruiter](/api-reference/v2/profiles/search-people-recruiter) → keep the candidate's `hire_identity_urn`.
2. `create_project` `{ "name": "Growth Marketer — Paris" }` → keep `project_urn` (or pick one from `list_projects`).
3. `add_to_project` `{ "project_urn", "candidate_urn": <hire_identity_urn> }` → the candidate lands in "uncontacted".
4. After contacting them, `move_candidate` with `"state": "contacted"`.
