## Overview

These actions manage a connected **email** mailbox. They run on the same [`POST /v2/messages`](/api-reference/v2/messages/send) endpoint (except attachment download, a GET). Each action costs **1 credit**.

Availability: all actions work on **Gmail**, **Outlook** and **IMAP/SMTP** mailboxes. Outlook's write actions (`mark_as_read`/`mark_as_unread`, `archive`, `trash`, `create_draft`) require a mailbox connected with the `Mail.ReadWrite` scope — reconnect mailboxes added earlier. On IMAP, `archive`/`trash` move the message to the mailbox's Archive/Trash folder (best-effort per server).

The `id` used below is the **provider message id** returned by [List Inbox](/api-reference/v2/messages/list-inbox#email-inbox) (`conversations[].id`) and [Get Conversation](/api-reference/v2/messages/get-conversation) (`messages[].id`).

## Read state, archive, trash

| `action` | Effect |
| --- | --- |
| `mark_as_read` | Marks the message read. |
| `mark_as_unread` | Marks it unread. |
| `archive` | Removes it from the inbox (keeps it in All Mail / Archive). |
| `trash` | Moves it to Trash. |

<ParamField body="account_id" type="string" required>The email account.</ParamField>
<ParamField body="action" type="string" required>One of `mark_as_read`, `mark_as_unread`, `archive`, `trash`.</ParamField>
<ParamField body="params" type="object" required>
  <Expandable title="params properties">
    <ParamField body="id" type="string" required>The provider message id (from list_inbox / get_conversation).</ParamField>
  </Expandable>
</ParamField>

```json Request
{ "account_id": "your-email-account-id", "action": "mark_as_read", "params": { "id": "1a09b5fe5c04c6d6" } }
```

```json 200
{
  "success": true,
  "data": { "status": "success", "message_id": "1a09b5fe5c04c6d6", "unread": false },
  "metadata": { "action": "mark_as_read", "account_id": "your-email-account-id", "credits_consumed": 1, "timestamp": "2026-09-14T12:00:00Z" }
}
```

## List labels

`action: "list_labels"` returns the mailbox's folders/labels (id, name, type) — use a label id in `list_inbox`'s `label_ids` to read another folder.

```json 200
{
  "success": true,
  "data": { "labels": [ { "id": "INBOX", "name": "INBOX", "type": "system" }, { "id": "Label_12", "name": "Clients", "type": "user" } ] },
  "metadata": { "action": "list_labels", "account_id": "your-email-account-id", "credits_consumed": 1, "timestamp": "2026-09-14T12:00:00Z" }
}
```

## Create a draft

`action: "create_draft"` saves a draft (not sent). Same body params as [Send](/api-reference/v2/messages/send#email) (`to`, `subject`, `message_text` / `html`, plus attachments via `media_*`), plus two optional ones:

<ParamField body="params.thread_id" type="string">
  File the draft inside an existing conversation instead of as a standalone draft: the `conversation_id` returned by `list_inbox` / `get_conversation`. When set, `to` defaults to the sender of the thread's last message and `subject` to `Re: <its subject>`; pass them to override. Gmail and Outlook thread the draft natively; on IMAP the conversation id is the thread's Message-ID and is used as the `In-Reply-To` header.
</ParamField>
<ParamField body="params.from_email" type="string">
  Write the draft from a send-as alias of the mailbox instead of its primary address (optional `from_name` for the display name). The alias must be configured on the mailbox: Gmail replaces an unverified alias with the primary address at send time, Outlook needs Send-As rights on it.
</ParamField>

```json Request
{ "account_id": "your-email-account-id", "action": "create_draft", "params": { "to": "prospect@example.com", "subject": "Draft", "message_text": "..." } }
```

```json Request (reply draft in a thread, from an alias)
{ "account_id": "your-email-account-id", "action": "create_draft", "params": { "thread_id": "19a2f3c4d5e6f708", "from_email": "sales@yourdomain.com", "message_text": "Following up on our call..." } }
```

```json 200
{
  "success": true,
  "data": { "status": "success", "draft_id": "r-5596439384536493289", "message_id": "<...@gmail.com>", "provider_message_id": "19a2f3c4d5e6f9ab", "thread_id": "19a2f3c4d5e6f708", "from_email": "sales@yourdomain.com" },
  "metadata": { "action": "create_draft", "account_id": "your-email-account-id", "credits_consumed": 1, "timestamp": "2026-09-14T12:00:00Z" }
}
```

`provider_message_id` is the draft message's own id (usable with `trash` to discard it) and `thread_id` its conversation: Gmail always returns both, Outlook returns them when `thread_id` was passed, IMAP returns `draft_folder` instead. `from_email` echoes the alias when one was used.

## Download attachment

`GET /v2/messages/attachment` streams an attachment's bytes. For email, pass the `message_id` and `attachment_id` from a message's `attachments[]` (via [Get Conversation](/api-reference/v2/messages/get-conversation)), plus an optional `filename`. **Gmail** and **Outlook**. Costs 1 credit.

<ParamField query="account_id" type="string" required>The email account.</ParamField>
<ParamField query="message_id" type="string" required>The provider message id carrying the attachment (`attachments[].message_id`).</ParamField>
<ParamField query="attachment_id" type="string" required>The attachment id (`attachments[].attachment_id`).</ParamField>
<ParamField query="filename" type="string">Optional filename for the download.</ParamField>

Returns the raw file with its `Content-Type`, or the standard JSON error envelope.
