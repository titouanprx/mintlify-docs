You connect an account and want its LinkedIn inbox inside your product. Pick the approach that matches how your product stores data.

| | On-demand + cache | Full sync (storage) | Managed inbox |
|---|---|---|---|
| You store | What your users opened | Every message | Nothing |
| History comes from | `list_inbox` / `get_conversation`, when needed | One [`/sync`](/api-reference/v2/accounts/sync-inbox), pushed to your webhook | `list_inbox` / `get_conversation`, answered by LinkupAPI |
| New messages | Real-time webhooks | Real-time webhooks | Already in `list_inbox` / `get_conversation` (webhooks optional) |
| Best for | Showing an inbox, light integrations | Search, analytics, a CRM that owns its data | A unibox without its own message storage |

## 1. On-demand with a cache

Nothing to import. You read LinkedIn when a user looks at something, and the webhook keeps what you cached up to date.

1. **Inbox screen** — [`list_inbox`](/api-reference/v2/messages/list-inbox), paginated with `cursor`. To refresh it, pass `since` (your last refresh, in ms): you only get the conversations that moved.
2. **Opening a conversation** — [`get_conversation`](/api-reference/v2/messages/get-conversation) with `count` (e.g. 25). When the user scrolls up, call it again with the returned `next_cursor` to load older messages.
3. **New messages** — a [webhook](/api-reference/v2/webhooks/introduction) subscribed to messages, with `message_type: "all"` to also get what the account sends. Append each `message` event to the conversation you cached, keyed by `metadata.conversation_urn`.

## 2. Full sync into your storage

You keep every message in your database. Import the history once, then let real time take over — everything arrives through **the same webhook, in the same format**.

1. **Create the webhook** (`events`: `all` or `message_received`, `message_type: "all"`).
2. **Call [`POST /v2/accounts/{account_id}/sync`](/api-reference/v2/accounts/sync-inbox)** right after connecting the account. LinkupAPI reads the inbox in the background and posts every message to your webhook, conversation by conversation.
3. **Real time** continues on the same webhook as soon as the account is connected. Messages delivered by real time are never sent again by the sync.

A sync POST carries up to 25 messages of one conversation under `events`. **Each item is exactly the `event` object of a real-time message webhook**, so one parser handles both:

One line normalizes both:

<CodeGroup>
```js Node.js
app.post("/webhooks/linkup", (req, res) => {
  const items = req.body.events ?? [req.body.event]; // sync = several, real time = one
  for (const event of items) handleMessage(event, req.body);
  res.sendStatus(200);
});
```

```python Python
items = body.get("events") or [body["event"]]  # sync = several, real time = one
for event in items:
    handle_message(event, body)
```
</CodeGroup>

<Warning>
  Synced messages can be months old. If you run automations on incoming messages (auto-replies, sequences stopping on a reply), skip the ones carrying `sync_id` or `catch_up: true`.
</Warning>

## 3. Managed inbox

LinkupAPI keeps the account's inbox on its side. You store nothing: read it with [`list_inbox`](/api-reference/v2/messages/list-inbox) and [`get_conversation`](/api-reference/v2/messages/get-conversation) whenever you need it — same parameters, same response.

- Holds the 100 most recent conversations with their latest messages, kept up to date in real time (new messages, read status, reactions, edits).
- Older conversations and messages are read from LinkedIn transparently: paginate with `cursor` / `next_cursor` as usual.
- Ready about 20 minutes after it is enabled.
- Classic inbox only: Sales Nav and Recruiter inboxes are read from LinkedIn as before.

<Note>
  Enabled per account on request: [support@linkupapi.com](mailto:support@linkupapi.com).
</Note>

## All approaches: nothing is lost

If the real-time connection of an account is interrupted (network, proxy, reconnection), LinkupAPI catches up the messages of the gap automatically and delivers them to your webhook as normal `message` events with a top-level `catch_up: true`.
