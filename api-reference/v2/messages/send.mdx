## Overview

Sends a message to a user identified by their profile URL, with optional media. Also sends a [Sales Nav InMail](#inmail) when you set `inmail: true` or pass a `recipient_urn`.

<Note>This endpoint consumes **1 credit** for text-only messages and **2 credits** when media is attached. An InMail consumes **1 InMail credit** from the account's premium seat (separate from your API credits — see [Balance](/api-reference/v2/messages/balance)).</Note>

<Note>When multiple media options are provided, the priority order is: `media_link` > `media_file` > `media_path`. Only one media attachment will be used.</Note>

<Note>An audio file (`.m4a`, `.mp3`, `.wav`, `.aac`) is delivered as a **native voice note**, not a file to download. LinkedIn caps them at 1 minute.</Note>

## Request

<ParamField header="x-api-key" type="string" required>
  Your API key for authentication.
</ParamField>

<ParamField body="account_id" type="string" required>
  The unique identifier of the account to use.
</ParamField>

<ParamField body="action" type="string" required>
  Must be `"send"`.
</ParamField>

<ParamField body="params" type="object" required>
  <Expandable title="params properties">
    <ParamField body="profile_url" type="string">
      URL of the recipient's profile. Used for both a standard message and an InMail (with `inmail: true`). Required unless you pass `recipient_urn`.
    </ParamField>
    <ParamField body="message_text" type="string" required>
      The text content of the message / InMail.
    </ParamField>
    <ParamField body="inmail" type="boolean" default={false}>
      Set to `true` to send an **InMail** (to a non-connection, via the premium seat) instead of a standard message. Consumes 1 InMail credit. Not needed when `recipient_urn` is a Sales Nav URN — that already forces the InMail path.
    </ParamField>
    <ParamField body="recipient_urn" type="string">
      **InMail** — the lead's `urn:li:fs_salesProfile:(...)` from the [lead search](/api-reference/v2/profiles/search-people-nav). Passing it sends an InMail (no `inmail: true` needed). Use this **or** `profile_url` + `inmail: true`.
    </ParamField>
    <ParamField body="subject" type="string">
      **InMail** — optional subject line (recommended for InMails). Ignored for standard messages; on its own it does **not** trigger an InMail.
    </ParamField>
    <ParamField body="media_link" type="string">
      A publicly accessible URL to a media file to attach.
    </ParamField>
    <ParamField body="media_file" type="object">
      A base64-encoded media file to attach.
      <Expandable title="media_file properties">
        <ParamField body="data" type="string" required>
          The base64-encoded file content.
        </ParamField>
        <ParamField body="filename" type="string" required>
          The filename including extension (e.g. `"document.pdf"`).
        </ParamField>
      </Expandable>
    </ParamField>
    <ParamField body="media_path" type="string">
      A server-side file path to a media file to attach.
    </ParamField>
    <ParamField body="voice_message" type="boolean" default={false}>
      Force the attached media to be sent as a **voice note**. Only needed when the filename carries no usable extension — an `.m4a`, `.mp3`, `.wav` or `.aac` file is detected on its own.
    </ParamField>
  </Expandable>
</ParamField>


## Response

<ResponseField name="success" type="boolean">
  Indicates whether the request was successful.
</ResponseField>

<ResponseField name="data" type="object">
  Details of the sent message. The shape differs between a standard message and an InMail.
  <Expandable title="standard message">
    <ResponseField name="status" type="string">
      `"success"` when the message was sent.
    </ResponseField>
    <ResponseField name="data" type="object">
      <Expandable title="properties">
        <ResponseField name="entityUrn" type="string">
          The unique URN of the sent message entity.
        </ResponseField>
        <ResponseField name="conversation_id" type="string">
          The URN of the conversation the message was sent in.
        </ResponseField>
        <ResponseField name="deliveredAt" type="integer">
          Unix epoch timestamp in **milliseconds**.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
  <Expandable title="InMail">
    <ResponseField name="status" type="string">
      `"success"` when the InMail was sent.
    </ResponseField>
    <ResponseField name="message" type="string">
      Human-readable result, e.g. `"InMail sent"`.
    </ResponseField>
    <ResponseField name="recipient_urn" type="string">
      The Sales Nav URN the InMail was sent to.
    </ResponseField>
    <ResponseField name="data" type="object">
      Raw send result: `{ "value": { "threadId": "...", "messageId": "..." } }`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="metadata" type="object">
  <Expandable title="metadata properties">
    <ResponseField name="action" type="string">
      The action that was performed (`"send"`).
    </ResponseField>
    <ResponseField name="account_id" type="string">
      The account ID used for the request.
    </ResponseField>
    <ResponseField name="credits_consumed" type="integer">
      Number of credits consumed (1 for text, 2 with media).
    </ResponseField>
    <ResponseField name="timestamp" type="string">
      ISO 8601 timestamp of the response.
    </ResponseField>
  </Expandable>
</ResponseField>

## InMail

Reaches someone you are not connected to, through the account's premium seat. Triggered by `inmail: true` or a `recipient_urn` — a `subject` alone never turns a message into an InMail. Prefer `recipient_urn` from the [lead search](/api-reference/v2/profiles/search-people-nav) when you have it.

```json
{
  "account_id": "your-account-id",
  "action": "send",
  "params": {
    "recipient_urn": "urn:li:fs_salesProfile:(...)",
    "subject": "Quick question",
    "message_text": "Hi ..."
  }
}
```

A profile that cannot be InMailed is rejected before any credit is spent. Credits come from the seat — see [Balance](/api-reference/v2/messages/balance).
