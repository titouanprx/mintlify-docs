---
title: 'Verify Checkpoint (2FA)'
api: 'POST /v2/checkpoint'
description: 'Submit a verification code to complete account connection'
---

Complete the connection of an account that returned `checkpoint_required` during login:

- **LinkedIn 2FA** — depending on the `challenge_type` used at login, submit the verification code or simply confirm the app challenge.
- **Email OAuth** — submit the authorization `code` received on your `redirect_uri` after the user consented on the Google/Microsoft screen. See [Connect a Mailbox](/api-reference/v2/email/connect-mailbox).

<Note>
  **1 credit** per request for LinkedIn. **Free** for email accounts.
</Note>

### Header Parameters

<ParamField header="x-api-key" type="string" required>
  Your API key
</ParamField>

### Body Parameters

<ParamField body="account_id" type="string" required>
  The account ID returned from the `/v2/login` endpoint with `checkpoint_required` status
</ParamField>

<ParamField body="code" type="string">
  LinkedIn: the verification code received via email, SMS, or authenticator app. Required when `challenge_type` is `code_challenge`; not needed for `app_challenge` — the user approves directly from the platform's mobile app. Email OAuth: the authorization code from your `redirect_uri` (always required).
</ParamField>

<ParamField body="state" type="string">
  Email OAuth only, optional: the `state` from your `redirect_uri`, to disambiguate concurrent connection flows on the same mailbox.
</ParamField>

### Response

<ResponseField name="success" type="boolean">
  Whether the verification was successful
</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="Properties">
    <ResponseField name="account_id" type="string">
      The account ID, now fully connected
    </ResponseField>
    <ResponseField name="status" type="string">
      `connected` — the account is ready to use
    </ResponseField>
  </Expandable>
</ResponseField>

### Challenge Types

- **`code_challenge`** — The user receives a verification code (email, SMS, or authenticator app). Submit the code in the `code` field.
- **`app_challenge`** — The user approves the login directly from the platform's mobile app. Once approved, call this endpoint with only the `account_id` (no `code` needed).

### Notes
- If the session has expired (LinkedIn) or the OAuth flow is stale (email), call `/v2/login` again to restart the process
- Once verified, the account status changes to `connected` and is ready for use
- The `account_id` remains the same — no need to update your integration
- Email: a failed code exchange leaves the pending flow intact — you can retry with a fresh code without restarting login
